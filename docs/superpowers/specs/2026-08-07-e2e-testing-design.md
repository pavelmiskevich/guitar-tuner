# Дизайн E2E-тестирования «Ночная репетиция» (guitar-tuner)

**Дата:** 2026-08-07
**Статус:** утверждён, готов к планированию реализации

---

## 1. Цель и границы

Продукт — PWA-тюнер с пятью экранами (тюнер, гриф, проверка аккорда, метроном, тренажёр слуха), настройками и офлайн-режимом. Сейчас в репозитории есть только модульные тесты Vitest (`tests/*.test.ts`, 21 тест) — они покрывают математику, DSP и синтезаторы, но ни один из них не проверяет, что продукт вообще собирается в работающее приложение.

Задача решается в два этапа:

1. **Разведочный прогон** — ручной проход продукта через браузерную автоматизацию, поиск реальных дефектов, отчёт.
2. **Постоянный сьют** — автоматизированные E2E-тесты в репозитории, запускаемые повторно.

Разведка идёт первой: писать автотесты против приложения, чьё фактическое поведение не проверено, — значит зафиксировать в тестах существующие баги как ожидаемое поведение.

### Не входит в объём

| Что | Почему |
|---|---|
| CI-пайплайн (GitHub Actions и т.п.) | В репозитории CI отсутствует; конфигурация будет к нему готова, но сам пайплайн — отдельная задача |
| Визуальные регрессии (`toHaveScreenshot`) | Градиентная аура, анимации и canvas-спектр дают нестабильные снимки |
| Реальный Safari / iOS | WebKit на Windows не эквивалентен Safari; проверяется только на устройстве |
| Нагрузочное и security-тестирование | Вне запроса |

## 2. Ключевые факты о продукте, влияющие на дизайн

Установлены чтением исходников, а не документации:

1. **Навигация — состояние React, а не роутер.** `App.tsx` рендерит одновременно и десктопную панель (`.desktop-nav`), и мобильный таб-бар (`.mobile-bottom-nav`); скрытие — чисто CSS. Следствие: текстовые селекторы (`getByText('Тюнер')`) находят два элемента и валят Playwright по strict mode. Нужны раздельные `data-testid`.

2. **Аудиодвижок — синглтон на уровне модуля.** `sharedAudioEngine` в `src/audio/audioEngine.ts` живёт вне React и не пересоздаётся при смене вкладки. Микрофон обязан переживать переключение экранов — это тестируемое требование.

3. **Точка внедрения фейкового микрофона.** `AudioEngine.start()` вызывает `navigator.mediaDevices.getUserMedia`, затем `audioContext.createMediaStreamSource(stream)`. Подмена `getUserMedia` на уровне окна полностью прозрачна для продукта.

4. **В тюнере уже есть числовые «зацепки».** Экран выводит `Измерено: X Гц` и `Цель: Y Гц`, команду `В СТРОЕ` / `ПОДТЯНУТЬ` / `ОСЛАБИТЬ` / `Сыграйте струну`, а чипы струн несут атрибут `data-state="idle|active|off|done"`. Это позволяет писать точные численные утверждения вместо сравнения картинок.

5. **Пороговые константы, заданные в коде** (их и проверяем):
   - шумовой порог DSP — `-65 dBFS`, порог пика NSDF — `0.25`;
   - затухание звука — `1200 мс` без валидного тона возвращает состояние «Сыграйте струну»;
   - автопереход в режиме Мастера — `1200 мс` удержания строя;
   - удержание выбранной струны — до `250` центов расхождения, дальше срабатывает автоопределение;
   - подсказка «Совет мастера» показывается при `cents > 15`;
   - порог «в строе» по умолчанию — `5` центов (настраивается).

6. **Состояние в `localStorage`:** `gt_tuning`, `gt_a4`, `gt_notation`, `gt_threshold`, `gt_theme`, а также `night_rehearsal_custom_tunings` (пользовательские строи) и `nr_ear_best_streak` (рекорд тренажёра). Тесты обязаны стартовать с чистого хранилища, иначе сценарии настроек протекают друг в друга.

7. **Экспорт SVG берёт первый `<svg>` документа.** `handleExportSVG` вызывает `document.querySelector('svg')`, а раньше грифа в DOM идут иконки lucide. Сценарий экспорта пишется так, чтобы отличить схему грифа от иконки, а не просто зафиксировать факт скачивания.

## 4. Фейковый микрофон

### 4.1 Принцип

`page.addInitScript` выполняется до загрузки приложения и заменяет `navigator.mediaDevices.getUserMedia` функцией, возвращающей поток из собственного `AudioContext`:

```
OscillatorNode(f0) ─┐
OscillatorNode(2f0)─┤
OscillatorNode(3f0)─┼→ GainNode → MediaStreamAudioDestinationNode → MediaStream
OscillatorNode(4f0)─┤
OscillatorNode(5f0)─┘
```

Продукт создаёт из этого потока `MediaStreamAudioSourceNode` в **своём** `AudioContext` — передача между контекстами через `MediaStream` штатно поддерживается Chromium.

### 4.2 Почему не чистый синус

McLeod Pitch Method работает по нормализованной автокорреляции. На идеальном синусе пики NSDF на периоде и на удвоенном периоде почти равны, и детектор может устойчиво выдавать октавную ошибку. Тест на синусе проверял бы артефакт мока, а не продукт. Поэтому сигнал содержит основной тон и 4 гармоники с убывающей амплитудой (≈ `1 / h`), что соответствует спектру щипковой струны.

Суммарный уровень выставляется около `-25 dBFS` — заведомо выше шумового порога `-65 dBFS` и заведомо ниже клиппинга.

### 4.3 API внутри страницы

```
window.__fakeMic.setFrequency(82.41)    // произвольная частота, Гц
window.__fakeMic.setCents('E2', +7)     // нота ± центы; частота считается по A4 из аргумента
window.__fakeMic.silence()              // глушит выход, оставляя поток живым
window.__fakeMic.stop()                 // останавливает генератор
```

`setCents` принимает третьим аргументом эталон A4 (по умолчанию 440) — это нужно сценарию с A4 = 432 Гц.

Смена частоты идёт через `setValueAtTime` на всех осцилляторах одновременно, без пересоздания графа: пересоздание рвало бы `MediaStream` и заставляло продукт заново запрашивать микрофон.

### 4.4 Дымовой тест на реальном захвате

Один тест (`smoke-realmic.spec.ts`) запускается с флагами `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream --use-file-for-fake-audio-capture=<wav>` и WAV-сэмплом открытой шестой струны. Он проверяет только одно: продукт корректно распознаёт ноту при настоящем WebRTC-захвате. Это страховка от ситуации, когда весь остальной сьют зелёный лишь потому, что мок оказался слишком удобным.

## 6. Общие фикстуры

`tests/e2e/fixtures/test-base.ts` расширяет базовый `test`:

- **Чистое состояние.** Перед каждым тестом `localStorage` очищается до загрузки приложения (через `addInitScript`), чтобы не зависеть от порядка выполнения.
- **Страж консоли.** Подписка на `console` (уровень `error`) и `pageerror`; любое срабатывание валит тест с текстом сообщения. Это ловит регрессии, которых нет в явных утверждениях.
- **Фейковый микрофон.** Инжектится во все тесты, но активируется только явным вызовом из теста — экраны без аудио не должны зависеть от генератора.

Артефакты при падении: трейс, скриншот, видео (`trace: 'retain-on-failure'`).

### 7.2 `navigation.spec.ts`

- Переключение всех пяти экранов на десктопе; `header-subtitle` отражает активный экран.
- На мобильном вьюпорте десктопная панель скрыта, таб-бар виден и работает.
- **Отсутствие горизонтального скролла** на обоих вьюпортах на каждом из пяти экранов: `documentElement.scrollWidth <= clientWidth`.
- **Живучесть микрофона**: включить микрофон на тюнере → перейти на гриф → вернуться → `mic-status` по-прежнему активен (проверка синглтона `sharedAudioEngine`).

### 7.3 `settings.spec.ts`

- A4 принимает границы диапазона 415–466 и отражается в подзаголовке шапки.
- Три системы нотации: в немецкой нота `B` отображается как `H`, в сольфеджио — как `Си`.
- Порог точности меняет ширину зоны «В СТРОЕ»: при пороге 2¢ отклонение в 4¢ уже даёт «ПОДТЯНУТЬ»/«ОСЛАБИТЬ».
- Переключение темы выставляет `data-theme` на `<html>`.
- Конструктор пользовательского строя создаёт строй, он применяется и сохраняется.
- Все настройки переживают перезагрузку страницы.

### 7.4 `fretboard.spec.ts`

- Переключение режимов Исследование / Гаммы / Аккорды меняет содержимое SVG.
- Выбор тоники и гаммы подсвечивает ожидаемое число ступеней.
- Каподастр смещает подсвеченные позиции; леворукий режим зеркалит гриф.
- Экспорт SVG инициирует загрузку файла (событие `download`).
- **Deep linking**: кнопка «Поделиться» кладёт в буфер обмена ссылку с параметрами `mode`, `root`, `scale`, `capo`; открытие URL с таким хэшем восстанавливает режим, тонику и гамму. Важно: состояние **не** пишется в адресную строку само по себе — `handleShareLink` только копирует ссылку, `window.location.hash` не меняется.

### 7.5 `chord-check.spec.ts`

- Диаграмма аккорда отрисована, открытые (O) и глушёные (X) струны размечены.
- Режим арпеджио: подача корректных частот через фейковый микрофон приводит к отметке струн как прозвучавших.
- Режим удара: подача аккордового сигнала за отведённые 1.2 с даёт результат анализа.
- Кнопка перехода к настройке переключает на тюнер с зафиксированной проблемной струной.

### 7.6 `metronome.spec.ts`

- Старт и остановка; `metronome-toggle` меняет состояние.
- Размеры 2/4, 3/4, 4/4, 6/4 меняют число долей в такте.
- Tap-tempo: серия кликов с известным интервалом устанавливает соответствующий BPM (±10%).
- Четыре ритма переключаются, секвенсор показывает 16 шагов.
- **Проверка тайминга**: за фиксированный интервал число пройденных шагов секвенсора соответствует установленному BPM (±5%). Это единственный способ убедиться, что метроном действительно идёт по расписанию Web Audio, а не по «плавающему» таймеру.

### 7.7 `ear-training.spec.ts`

- Три режима переключаются, вопрос меняется соответственно.
- Правильный ответ увеличивает счёт и серию; неправильный обнуляет серию.
- Рекорд сохраняется в `localStorage` и переживает перезагрузку.

Проблема детерминизма: загаданная нота выбирается случайно и до ответа не показана. Решение — не угадывать её, а проверять инвариант независимо от того, какой вариант выбран:

- **Верный ответ:** тест кликает варианты по очереди до появления «Правильно!»; фиксирует счёт и серию непосредственно перед этим кликом и проверяет, что после него счёт и серия выросли.
- **Неверный ответ:** отдельный тест на свежей странице делает один клик; если попал в верный — повторяет на новом вопросе, пока не получит «Не совсем точно», и проверяет, что серия обнулилась.

Так тест не зависит от случайного выбора и не требует доступа к внутреннему состоянию игры.

### 7.8 `pwa.spec.ts`

- `manifest.json` отдаётся с кодом 200 и содержит обязательные поля (`name`, `start_url`, `display`, `icons`).
- Все иконки из манифеста доступны (200).
- Service Worker регистрируется: `navigator.serviceWorker.ready` резолвится.
- **Офлайн**: после первой загрузки `context.setOffline(true)` и перезагрузка — приложение открывается и показывает экран тюнера.

## 8. Обработка нестабильности

Аудио и анимации — главный источник мигающих тестов. Меры:

1. **Никаких фиксированных пауз** там, где можно ждать условие: используется `expect.poll` / `toPass` с разумным таймаутом вместо `waitForTimeout`.
2. **Прогрев детектора.** После подачи частоты тюнеру нужно несколько кадров `requestAnimationFrame`, чтобы буфер заполнился. Утверждения оборачиваются в `toPass` с таймаутом 3 с.
3. **Допуски заданы явно**: частота ±0.3 Гц, центы ±1, тайминг метронома ±5%, tap-tempo ±10%.
4. **Ретраи**: 1 повтор локально, 2 при `CI=true`. Тест, стабильно требующий повтора, считается дефектом теста и переписывается, а не «замазывается» ретраем.

## 10. Риски

| Риск | Митигация |
|---|---|
| Headless Chromium не прогоняет граф Web Audio без звукового устройства | Проверяется первым же шагом реализации на минимальном прототипе фейкового микрофона; при провале — переход на схему с `--use-file-for-fake-audio-capture` как основную |

| Добавление `data-testid` затрагивает продуктовый код | Только атрибуты, без изменения разметки и стилей; проверяется прогоном `npm run build` и модульных тестов |
