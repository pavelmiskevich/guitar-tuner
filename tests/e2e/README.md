# E2E-тесты

## Запуск

- `npm run test:e2e` — полный прогон (десктоп + мобильный + реальный микрофон)
- `npm run test:e2e:ui` — интерактивный режим
- `npm run test:e2e -- tuner.spec.ts` — одна спека
- `npm run test:e2e:explore` — разведочный проход, в обычный прогон не входит

Разведка отделена флагами `--grep-invert @exploration` / `--grep @exploration` в самих
скриптах, а не через `grepInvert` в конфиге: в Playwright 1.62.1 конфигурационный
`grepInvert` применяется раньше CLI-флагов, и переопределить его из командной строки
невозможно.

Сервер поднимается автоматически: `npm run build && vite preview --port 4173`.

## Фейковый микрофон

`tests/e2e/fixtures/fake-mic.ts` подменяет `getUserMedia` синтезированным сигналом.
Управление из теста:

    await page.evaluate((f) => window.__fakeMic.setFrequency(f), 82.41);
    await page.evaluate(() => window.__fakeMic.setCents('E2', -20));
    await page.evaluate(() => window.__fakeMic.silence());

Сигнал содержит основной тон и четыре гармоники: на чистом синусе детектор
McLeod даёт октавные ошибки.

## Страж консоли

`fixtures/test-base.ts` состоит из двух слоёв:

- `consoleGuardTest` — базовый слой: очищает `localStorage` перед тестом и роняет
  тест при любом `console.error` или необработанном исключении страницы. Микрофон
  не трогает.
- `test` — `consoleGuardTest`, расширенный `installFakeMic`. Это то, что импортируют
  почти все спеки.

Страж консоли работает в обоих слоях, поэтому активен в любой спеке, использующей
хотя бы один из них. Если это мешает — чинить приложение, а не глушить стража.

Два теста намеренно импортируют `consoleGuardTest` напрямую, минуя `test`, —
им нужен страж, но не фейковый микрофон:

- `smoke-realmic.spec.ts` — единственная спека, которая гоняет реальный путь
  захвата WebRTC (через `--use-file-for-fake-audio-capture`); фейковый микрофон
  здесь подменил бы именно то, что тест обязан проверять.
- `fixtures/fake-mic.spec.ts` — тестирует сам `installFakeMic`, поэтому
  устанавливает его вручную внутри теста, а не через фикстуру.

Остальные спеки продолжают импортировать `test` без изменений.

## Селекторы

Только `data-testid`. Текстовые селекторы ненадёжны: десктопная и мобильная
навигация присутствуют в DOM одновременно и скрыты лишь стилями.

## Читай значения из DOM одним снимком

Детектор высоты тона не переключается на новое значение мгновенно: пока анализатор
«домотает» окно анализа до новой частоты, показания на экране колеблются (наблюдалось
до 30¢ разброса и даже кратковременная смена знака) прежде чем осесть на стабильном
значении. Если тест сначала дожидается нужного текста через `toPass`, а затем читает
DOM ещё раз отдельным вызовом для числового разбора — между этими двумя чтениями
значение может успеть измениться, и тест падает не по вине продукта, а по вине теста
(см. `tests/e2e/tuner.spec.ts:36`, «на заниженной струне требует подтянуть»). Правило:
всё чтение и все проверки одного значения должны происходить за одно обращение к DOM
внутри одного и того же блока `toPass`.
