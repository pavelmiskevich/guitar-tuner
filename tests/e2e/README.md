# E2E-тесты

## Запуск

- `npm run test:e2e` — полный прогон (Chromium: десктоп, мобильный, реальный микрофон; Firefox и WebKit — интерфейс без микрофона)
- `npm run test:e2e -- --project=chromium-desktop` — один браузер
- `npm run test:e2e:ui` — интерактивный режим
- `npm run test:e2e -- tuner.spec.ts` — одна спека
- `npm run test:e2e:explore` — разведочный проход, в обычный прогон не входит
- `npm run test:e2e:perf` — замер кадров тюнера при шестикратном замедлении процессора (`perf.spec.ts`, только Chromium), в обычный прогон не входит

Разведка и замер отделены флагами `--grep-invert "@exploration|@perf"` / `--grep @exploration` в самих
скриптах, а не через `grepInvert` в конфиге: в Playwright 1.62.1 конфигурационный
`grepInvert` применяется раньше CLI-флагов, и переопределить его из командной строки
невозможно.

Сервер поднимается автоматически: `npm run build && vite preview --port 4173`. Порт можно
сменить переменной `E2E_PORT` — например, чтобы параллельно гонять E2E из двух рабочих копий.

## Браузеры

Анализ звука проверяется в Chromium: фейковый микрофон опирается на Web Audio, и
поведение этой связки в других движках расходится в мелочах, к продукту не
относящихся. Firefox (`firefox-desktop`) и WebKit (`webkit-mobile`, профиль
iPhone) гоняют спеки интерфейса — навигация, гриф, настройки, метроном, темы,
PWA, устойчивость, доступность (`a11y.spec.ts`: axe и клавиатура); список — `NO_MIC_SPECS` в `playwright.config.ts`. WebKit
ближе всего к Safari на iOS, под который в коде есть отдельные ветки.

Тест внутри этих спек, которому всё же нужен микрофон, помечается тегом:

    test('строгий порог сужает зону «В СТРОЕ»', { tag: '@mic' }, async ({ page }) => {

Firefox и WebKit такие тесты пропускают. Ещё два тега отмечают ограничения
тестовых браузеров, а не приложения:

- `@audio-clock` — тест ждёт, что доли метронома идут по часам `AudioContext`.
  Firefox на Linux-раннере CI без звуковой карты часы не двигает; такие тесты
  Firefox пропускает.
- `@sw-offline` — перезагрузка в офлайне через service worker. WebKit падает на
  ней с внутренней ошибкой движка; такие тесты WebKit пропускает. Мобильная раскладка выбирается по
`testInfo.project.use.isMobile`, а не по имени проекта. Тест с буфером обмена
начинается с `grantClipboard(context)`: выдавать на него разрешения Playwright
умеет только в Chromium, в остальных браузерах тест пропускается.

WebKit для Windows, который ставит Playwright, собран без Web Audio и без
`mediaDevices`: локально под Windows в нём падают метроном и PWA-тесты со звуком.
Проверка WebKit — в CI на Linux.

### Тишина на динамиках

Безголовый Chromium звук никуда не выводит, а Firefox и WebKit играют синтезатор
грифа и метроном в настоящие колонки. Поэтому `consoleGuardTest` подменяет
`destination` у каждого аудиоконтекста усилителем с нулевой громкостью. Если
тесту понадобится настоящий выход — снимайте подмену явно, а не удаляйте её.

## Фейковый микрофон

`tests/e2e/fixtures/fake-mic.ts` подменяет `getUserMedia` синтезированным сигналом.
Управление из теста:

    await page.evaluate((f) => window.__fakeMic.setFrequency(f), 82.41);
    await page.evaluate(() => window.__fakeMic.setCents('E2', -20));
    await page.evaluate(() => window.__fakeMic.setLevel(-60));
    await page.evaluate(() => window.__fakeMic.silence());
    await page.evaluate(() => window.__fakeMic.denyAccess());
    await page.evaluate(() => window.__fakeMic.endTracks());

Сигнал содержит основной тон и четыре гармоники: на чистом синусе детектор
McLeod даёт октавные ошибки.

### Проверяйте на реалистичной громкости

По умолчанию сигнал идёт на −26 dBFS. Это заметно громче живой гитары через
микрофон телефона (около −60 dBFS), и на такой громкости тест спектрограммы
проходил при фактически неработающем расчёте: полосы считались от абсолютных
децибел, и на тихом входе все прижимались к нулю. Если тест зависит от уровня
сигнала, ставьте его явно через `setLevel`.

### Проверяйте и путь отказа

`denyAccess()` заставляет `getUserMedia` отклоняться с `NotAllowedError`, как при
запрете доступа. До его появления ветка ошибки микрофона не была покрыта вовсе,
и пользователь застрял на баннере, который не объяснял, где менять разрешение.

`endTracks()` обрывает уже выданные приложению дорожки с событием `ended` — как
при отзыве разрешения или отключении гарнитуры. Без обработки этого события
приложение показывало «Микрофон активен», хотя звука больше не было (#8).

## Страж консоли

`fixtures/test-base.ts` состоит из двух слоёв:

- `consoleGuardTest` — базовый слой: очищает `localStorage` перед тестом и роняет
  тест при любом `console.error` или необработанном исключении страницы. Микрофон
  не трогает.
- `test` — `consoleGuardTest`, расширенный `installFakeMic`. Это то, что импортируют
  почти все спеки.

Страж консоли работает в обоих слоях, поэтому активен в любой спеке, использующей
хотя бы один из них. Если это мешает — чинить приложение, а не глушить стража.

Два теста намеренно импортируют `consoleGuardTest` напрямую, минуя `test`, —
им нужен страж, но не фейковый микрофон:

- `smoke-realmic.spec.ts` — единственная спека, которая гоняет реальный путь
  захвата WebRTC (через `--use-file-for-fake-audio-capture`); фейковый микрофон
  здесь подменил бы именно то, что тест обязан проверять.
- `fixtures/fake-mic.spec.ts` — тестирует сам `installFakeMic`, поэтому
  устанавливает его вручную внутри теста, а не через фикстуру.

Остальные спеки продолжают импортировать `test` без изменений.

## Не подгоняйте раскладку под размеры устройства

Кнопку «Следующий вопрос» в тренажёре слуха дважды «починили» подбором высот —
и оба раза она всё равно уезжала под сгиб на реальном iPhone. Причины две:
доступная высота Safari меняется на ходу при сворачивании адресной строки, а
`env(safe-area-inset-bottom)` под эмуляцией равен нулю против 34px на устройстве.
Замер в эмуляторе поэтому систематически оптимистичнее реальности.

Работающее решение — не зависеть от высоты вообще: блок прижат к низу экрана.
Тест проверяет это на вьюпорте 390×480, заведомо меньшем любого телефона.

## Селекторы

Только `data-testid`. Текстовые селекторы ненадёжны: десктопная и мобильная
навигация присутствуют в DOM одновременно и скрыты лишь стилями.

## Читай значения из DOM одним снимком

Детектор высоты тона не переключается на новое значение мгновенно: пока анализатор
«домотает» окно анализа до новой частоты, показания на экране колеблются (наблюдалось
до 30¢ разброса и даже кратковременная смена знака) прежде чем осесть на стабильном
значении. Если тест сначала дожидается нужного текста через `toPass`, а затем читает
DOM ещё раз отдельным вызовом для числового разбора — между этими двумя чтениями
значение может успеть измениться, и тест падает не по вине продукта, а по вине теста
(см. `tests/e2e/tuner.spec.ts:36`, «на заниженной струне требует подтянуть»). Правило:
всё чтение и все проверки одного значения должны происходить за одно обращение к DOM
внутри одного и того же блока `toPass`.
