# Техническое задание
## Веб-приложение «Гитарный гриф + тюнер по микрофону с анализом аккорда»

**Версия:** 1.0 (черновик для согласования)
**Дата:** 31.07.2026
**Тип документа:** функционально-техническое задание (ФТТ/SRS)
**Статус:** требует согласования по разделам 2.4 (допущения) и 12 (открытые вопросы)

---

## 1. Общие сведения

### 1.1. Назначение системы

Веб-приложение (SPA, работает в браузере без установки) для гитаристов, решающее три задачи:

1. **Визуализация грифа** — интерактивная схема грифа с нотами, интервалами, гаммами и аккордами для произвольного строя и количества струн.
2. **Монофонический тюнер** — настройка гитары по одной струне через микрофон устройства с индикацией «подтянуть / ослабить» и отклонением в центах.
3. **Полифонический анализ аккорда** — по звучанию одного взятого аккорда определить, какие именно струны (ноты) расстроены и в какую сторону.

### 1.2. Целевая аудитория

| Сегмент | Доля (оценочно) | Ключевая потребность |
|---|---|---|
| Начинающие гитаристы | 55% | Настроить гитару, не понимая теории; подсказка «крутить туда» |
| Продолжающие / любители | 30% | Быстрая настройка, альтернативные строи, поиск аккордов на грифе |
| Преподаватели | 10% | Демонстрация грифа ученику, шаринг схем по ссылке |
| Опытные / студийные | 5% | Точность ≤1 цента, компенсация растянутого строя, нестандартные строи |

### 1.3. Платформа и ограничения среды

- Клиентское веб-приложение, 100% логики в браузере. Аудио **никогда** не покидает устройство.
- Обязателен HTTPS (требование `getUserMedia`).
- Основной сценарий использования — **мобильный телефон в руках или на подставке рядом с гитарой**. Десктоп — вторичен, но полностью поддерживается.
- Оффлайн-работа после первой загрузки (PWA).

### 1.4. Глоссарий

| Термин | Определение |
|---|---|
| **Цент (cent)** | 1/100 полутона. Отклонение в центах: `1200 · log₂(f_измер / f_целев)` |
| **F0** | Основная частота (fundamental) звучащей ноты |
| **Партиал / гармоника** | Обертон с номером *h*; для идеальной струны `f_h = h · F0` |
| **Негармоничность (inharmonicity)** | Смещение обертонов вверх из-за жёсткости струны: `f_h = h·F0·√(1+B·h²)`, `B ≈ 10⁻⁵…10⁻⁴` |
| **NSDF** | Normalized Square Difference Function — база метода MPM определения высоты тона |
| **Строй (tuning)** | Набор целевых нот для каждой струны, от 6-й (самой толстой) к 1-й |
| **Аппликатура (voicing)** | Конкретное расположение аккорда на грифе: лад для каждой струны или «глушить» |
| **Онсет (onset)** | Момент атаки звука |
| **Кларити (clarity)** | Мера уверенности детектора высоты тона, 0…1 |
| **A4** | Эталонная частота ноты ля первой октавы, по умолчанию 440 Гц |

## 2. Цели, метрики и границы проекта

### 2.1. Цели продукта

- **Ц1.** Пользователь настраивает 6 струн с нуля быстрее чем за 90 секунд без обучения.
- **Ц2.** Пользователь получает ответ на вопрос «что расстроено?» одним ударом по струнам, не перебирая струны по одной.
- **Ц3.** Приложение работает на телефоне с встроенным микрофоном в бытовых условиях (комната, фоновый шум до ~50 дБ SPL).
- **Ц4.** Интерфейс минималистичен и mobile-first: экран тюнера считывается за 1 секунду боковым взглядом с расстояния вытянутой руки, без лишних элементов и обучения.

### 2.2. Метрики успеха

| Метрика | Целевое значение |
|---|---|
| Точность в установившемся режиме (чистый сигнал) | ±1 цент |
| Точность на реальных записях гитары | ±2 цента (95-й перцентиль) |
| Доля октавных ошибок детектора | < 0.5% кадров |
| Задержка «звук → обновление стрелки» | ≤ 60 мс |
| Время до первого валидного определения после щипка | ≤ 250 мс |
| Полный цикл настройки 6 струн (медиана, тест на пользователях) | ≤ 90 с |
| Корректность полифонического анализа (см. 5.3.9) | ≥ 90% струн при расстройке 5–50 центов |

### 2.3. Вне границ проекта (MVP)

- Регистрация, аккаунты, синхронизация между устройствами.
- Метроном, драм-машина, библиотека песен/табулатур, распознавание проигранной мелодии.
- Настройка через линейный вход/аудиоинтерфейс (в MVP только микрофон; архитектурно не запрещено).
- Автоматическое определение аккорда «на слух» без выбора пользователя (см. п. 5.3.10 — опция фазы 3).
- Серверная часть, БД, backend-аналитика на персональных данных.

### 2.4. Допущения, требующие подтверждения заказчиком

| # | Допущение |
|---|---|

## 3. Пользовательские сценарии (User Stories)

### US-1. Быстрая настройка новичком
> Я новичок. Открываю сайт, разрешаю микрофон, дёргаю любую струну. Приложение само понимает, какая это струна, и показывает крупную стрелку и слово «Подтянуть». Кручу колок, стрелка идёт к центру, экран становится зелёным и вибрирует. Перехожу к следующей струне.

**Критерий приёмки:** ни одного обязательного действия, кроме разрешения микрофона и щипка струны.

### US-2. Проверка «что расстроено» аккордом
> Беру аккорд Am и бью по струнам. Приложение показывает схему аккорда, где 2-я струна подсвечена красным с подписью «−18 ¢ · подтянуть», остальные зелёные. Я подтягиваю только 2-ю струну.

### US-3. Альтернативный строй
> Хочу DADGAD. Выбираю пресет, гриф и тюнер сразу переключаются на новые целевые ноты; ссылку со строем отправляю ученику.

### US-4. Изучение грифа
> Выбираю тональность A и лад «дорийский» — на грифе подсвечиваются все ноты гаммы, тоники выделены. Переключаю подписи с названий нот на номера ступеней.

### US-5. Настройка на репетиции в шуме
> Вокруг шумно. Включаю режим «строгий шумоподавитель» и ставлю телефон близко к деке; тюнер игнорирует посторонние звуки и не «скачет».

### US-6. Преподаватель
> Показываю ученику аккорд на большом экране, кликаю по ладам и составляю свою аппликатуру, сохраняю ссылку.

## 4. Информационная архитектура и экраны

### 4.1. Карта экранов

```
/                       Главная = Гриф (fretboard) + нижняя панель режимов
├── /tuner              Тюнер (моно, по одной струне)
├── /chord-check        Анализ аккорда
├── /settings           Настройки
├── /about              О приложении / приватность / инструкция
└── модальные:
    ├── Онбординг (3 шага)
    ├── Запрос доступа к микрофону + объяснение
    ├── Выбор строя (пресеты + кастом)
    ├── Выбор аккорда (библиотека + ручной ввод на грифе)
    └── Ошибки (доступ запрещён, нет устройства, слишком тихо/шумно)
```

Навигация на мобильном — нижний таб-бар из трёх пунктов: **Гриф · Тюнер · Аккорд**. На десктопе — гриф и панель тюнера могут отображаться одновременно (двухколоночная раскладка ≥1024 px).

### 4.2. Общий принцип отображения

Гриф — единый переиспользуемый компонент; тюнер и анализ аккорда **подсвечивают на нём струны**, а не рисуют собственные схемы. Это ключевое связующее решение продукта: пользователь всегда видит один и тот же гриф.

| FR-TN-23 | **Автоопределение струны**: ближайшая по центам целевая нота текущего строя, если \|Δ\| < 150 ¢; при неоднозначности (две цели ближе 150 ¢ — актуально для 12-струнных и открытых строёв) — приоритет струне, не отмеченной как настроенная, и с большей корреляцией по обертонам. | M |
| FR-TN-24 | Ручная фиксация струны: тап по струне на грифе или по кнопке 6…1 блокирует цель; блокировка снимается кнопкой «Авто». | M |
| FR-TN-25 | Крупная визуализация: стрелка/шкала от −50 до +50 ¢ (нелинейная шкала: центральные ±10 ¢ занимают 50% ширины для точной доводки), число центов, название целевой ноты, измеренная частота в Гц. | M |
| FR-TN-26 | Режим «Хроматический» (цель — ближайшая нота 12-ступенного строя вне зависимости от строя) переключателем. | S |
| FR-TN-27 | Генератор эталонного тона для настройки на слух (нота текущей струны, sine/струнный тембр). | C |
| FR-TN-28 | Поддержка растянутого строя (stretch tuning) — компенсация негармоничности: опциональные поправки в центах на струну, пресет «как у рояля»/«ручные поправки ±10 ¢ на струну». | C |
| FR-TN-29 | История настройки сессии: сколько центов было в начале — для мотивации и для диагностики «строй уплывает». | C |

### 5.3. Модуль «Анализ аккорда» (FR-CH)

Ключевая и наиболее рискованная функция. Реализуется двумя режимами; **режим A обязателен как гарантированно работающий, режим B — целевой**.

#### 5.3.1. Общие требования

| ID | Требование | Приор. |
|---|---|---|
| FR-CH-01 | Перед анализом пользователь задаёт **ожидаемую аппликатуру**: выбором из библиотеки, вводом на грифе или кнопкой «открытые струны» (все 6 открытых струн текущего строя). Без ожидаемой аппликатуры невозможно однозначно сопоставить обнаруженные ноты со струнами. | M |
| FR-CH-02 | Результат анализа: для каждой звучащей струны — отклонение в центах, направление («подтянуть»/«ослабить»), уровень уверенности (высокий/средний/нет данных), визуализация прямо на схеме аккорда на грифе. | M |
| FR-CH-03 | Список результатов сортируется по модулю отклонения; расстроенные струны выносятся наверх с кнопкой «Настроить эту струну» → переход в моно-тюнер с зафиксированной струной. | M |
| FR-CH-04 | При недостаточной уверенности по струне — честный ответ «не удалось определить», а не выдуманное значение, и подсказка «сыграйте струны по очереди». | M |

#### 5.3.2. Режим A — «Арпеджио» (обязательный, MVP)

| ID | Требование | Приор. |
|---|---|---|
| FR-CH-05 | Пользователь медленно перебирает струны сверху вниз (или по подсказке приложения). Система детектирует онсеты, сегментирует сигнал по нотам и применяет к каждому сегменту монофонический детектор (5.2.2). | M |
| FR-CH-06 | Детектор онсетов: спектральный поток (spectral flux) с адаптивным порогом, минимальный интервал между онсетами 80 мс. | M |
| FR-CH-07 | Сопоставление сегментов со струнами: по порядку следования (при известном направлении удара) с перекрёстной проверкой по ближайшей ожидаемой ноте. Пропущенные/лишние онсеты обрабатываются алгоритмом выравнивания последовательностей (DTW/Нидлмана-Вунша по нотам). | M |
| FR-CH-08 | Прогресс-индикатор: 6 ячеек струн заполняются по мере распознавания; неопознанные подсвечиваются с подсказкой «повторите 3-ю струну». | M |
| FR-CH-09 | Учитывать наложение звучания (предыдущая струна ещё звучит): анализ ведётся в окне 60–250 мс после онсета с приоритетом наиболее энергичной новой компоненты. | M |

#### 5.3.3. Режим B — «Один удар по струнам» (полифонический)

| ID | Требование | Приор. |
|---|---|---|
| FR-CH-10 | Захват фрагмента: от детектированного онсета удара + 60 мс (пропуск атаки) длительностью 500–1200 мс. Накопление 3–8 перекрывающихся кадров. | M |
| FR-CH-11 | Спектральный анализ: окно Ханна, N = 16384 при 48 кГц (~341 мс, разрешение 2.93 Гц), дополнение нулями ×4, уточнение частоты пиков параболической интерполяцией по логарифмической амплитуде **и** методом мгновенной фазы. Требуемая точность локализации партиала — ≤ 0.05 Гц на низких партиалах. | M |
| FR-CH-12 | Альтернативно/дополнительно — CQT (constant-Q) с разрешением ≥ 36 бинов на октаву для устойчивой сегментации по нотам. | S |
| FR-CH-13 | **Матчинг с моделью**: для каждой ожидаемой ноты аппликатуры строится модель партиалов `f_h = h·F0·√(1 + B·h²)`, h = 1…8, B берётся из таблицы по номеру струны/калибру (диапазон 1·10⁻⁵ … 2·10⁻⁴) либо оценивается по данным. В окрестности ±70 центов от каждого модельного партиала ищется спектральный пик. | M |
| FR-CH-14 | **Разрешение коллизий**: партиал исключается из оценки, если ближе чем на 30 центов к нему расположен модельный партиал другой струны (октавы, квинты, унисоны — типичны для открытых аккордов, например E2/E3/E4 в аккорде E). У каждой струны должно остаться ≥ 2 «чистых» партиала, иначе уверенность понижается. | M |
| FR-CH-15 | **Оценка отклонения струны**: взвешенная медиана по чистым партиалам `Δ_h = 1200·log₂(f_изм,h / f_модель,h)`, веса ∝ амплитуде партиала и обратно ∝ h. Разброс оценок > 20 центов → уверенность «низкая». | M |
| FR-CH-16 | Оценка уверенности по струне: функция от числа чистых партиалов, их SNR над локальным шумовым полом (порог 10 дБ) и согласованности. Три градации: высокая / средняя / нет данных. | M |
| FR-CH-17 | Обработка приглушённых и не сыгранных струн: если энергии на F0 и партиалах нет — статус «не прозвучала», без ошибки. | M |
| FR-CH-18 | Ограничение по расстройке: корректно определять отклонения в диапазоне ±60 центов. При отклонении > 100 центов (нота фактически другая) — вывод «струна расстроена очень сильно, настройте её по одной». | M |
| FR-CH-19 | Инструкция пользователю в интерфейсе: «медленно ударьте по всем струнам один раз и дайте им звучать 1–2 секунды», с анимацией и обратным отсчётом захвата. | M |
| FR-CH-20 | Повторный анализ по кнопке; агрегация результатов нескольких ударов (медиана по 2–3 попыткам) для повышения надёжности. | S |
| FR-CH-21 | Диагностический режим (скрыт в настройках разработчика): отображение спектра, найденных пиков, модельных партиалов и назначений — для отладки и настройки порогов. | S |

#### 5.3.4. Автоопределение аккорда (опция)

| ID | Требование | Приор. |
|---|---|---|
| FR-CH-22 | Распознавание сыгранного аккорда без выбора пользователем: хрома-вектор из CQT + сопоставление с шаблонами аккордов; результат предлагается как «Похоже, вы играете Am — верно?» с подтверждением и выбором аппликатуры. | C |

### 7.3. Поток данных аудио

```
Микрофон
  → MediaStreamSourceNode
  → capture.worklet (кольцевой буфер 32768, RMS, детект клиппинга, онсеты)
  → pitch.worklet / WASM (окно, децимация, NSDF/FFT)
  → postMessage {f0, clarity, rms, timestamp} с частотой ~50 Гц
  → main thread: сглаживание, привязка к целевой ноте, расчёт центов
  → store → React → SVG-индикатор (requestAnimationFrame)
```

Обмен между потоками — через `SharedArrayBuffer` при доступности (нужны COOP/COEP-заголовки), иначе `postMessage` со структурой фиксированного размера. Никаких аллокаций в аудиопотоке в горячем цикле.

### 7.4. Ключевые модели данных

```ts
type NoteName = 'C'|'C#'|'D'|'D#'|'E'|'F'|'F#'|'G'|'G#'|'A'|'A#'|'B';

interface Pitch {            // абсолютная высота
  midi: number;              // 40 = E2 (6-я струна стандарта)
  name: NoteName;
  octave: number;            // научная нотация: E2 = 82.41 Гц
}

interface StringSpec {
  index: number;             // 1 = самая тонкая
  open: Pitch;               // нота открытой струны
  gauge?: number;            // калибр, дюймы — для толщины линии и оценки B
  inharmonicityB?: number;   // коэффициент негармоничности
}

interface Tuning {
  id: string;
  name: string;              // 'Standard E', 'DADGAD', ...
  instrument: 'guitar'|'bass'|'ukulele'|'guitar12';
  strings: StringSpec[];     // от 6-й к 1-й
  isCustom: boolean;
}

interface FretboardState {
  tuning: Tuning;
  frets: { from: number; to: number };
  capo: number | null;
  orientation: 'horizontal'|'vertical';
  leftHanded: boolean;
  labelMode: 'note'|'degree'|'fret'|'interval'|'none';
  highlight: | { kind: 'scale'; root: NoteName; scaleId: string }
             | { kind: 'chord'; voicing: Voicing }
             | { kind: 'none' };
}

interface Voicing {          // аппликатура
  chordId: string;           // 'Am', 'C/E', 'Fmaj7' ...
  frets: (number | 'x')[];   // по струнам от 6-й к 1-й; 0 = открытая
  fingers?: (number | null)[];
  barre?: { fret: number; fromString: number; toString: number };
}

interface PitchEstimate {    // выход детектора
  frequency: number;         // Гц
  clarity: number;           // 0..1
  rms: number;               // dBFS
  timestamp: number;         // performance.now()
}

interface TuningReading {    // состояние тюнера для UI
  targetStringIndex: number;
  targetPitch: Pitch;
  targetFrequency: number;
  measuredFrequency: number;
  cents: number;
  direction: 'tighten'|'loosen'|'in-tune';
  zone: 'green'|'yellow'|'red';
  stability: 'stable'|'unstable';
  confidence: number;
}

interface ChordAnalysisResult {
  voicing: Voicing;
  strings: Array<{
    stringIndex: number;
    expected: Pitch;
    measuredFrequency: number | null;
    cents: number | null;
    direction: 'tighten'|'loosen'|'in-tune'|null;
    confidence: 'high'|'medium'|'none';
    status: 'ok'|'off'|'not-played'|'undetermined'|'very-off';
    usedPartials: number;
  }>;
  capturedAt: number;
  attempts: number;
}
```

### 7.5. Расчётные формулы (справочно для реализации)

| Величина | Формула |
|---|---|
| Частота ноты | `f(m) = A4 · 2^((m − 69)/12)` |
| Отклонение | `cents = 1200 · log₂(f_изм / f_цель)` |
| Ближайшая нота | `m = round(69 + 12·log₂(f/A4))` |
| Позиция лада | `d(n) = L · (1 − 2^(−n/12))` |
| Партиал с негармоничностью | `f_h = h · F0 · √(1 + B·h²)` |
| Стандартный строй (A4=440) | E2 82.407, A2 110.000, D3 146.832, G3 195.998, B3 246.942, E4 329.628 Гц |

## 8. Требования к интерфейсу

### 8.1. Принципы визуального дизайна (минимализм)

> **Визуальное направление утверждено: «Ночная репетиция»** (индиговая тёмная база, розовый = «расстроено», бирюзовый = «в строе»). Полный набор токенов, компонентов и правил — в Приложении В и в файле `brandbook-night-rehearsal.html`. Требования NFR-D-01…10 ниже остаются обязательными и ограничивают направление: свечение допускается только как носитель семантики строя.

Дизайн строится по принципу «инструмент, а не витрина»: пользователь держит телефон в одной руке, гитару — в другой, смотрит на экран урывками и с расстояния 40–80 см. Всё, что не помогает ответить на вопрос «куда крутить», удаляется.

| ID | Требование |
|---|---|
| NFR-D-01 | **Один экран — одна задача.** На экране тюнера не более 5 смысловых блоков (раздел 8.3); всё остальное убрано в настройки или скрыто до момента необходимости. |
| NFR-D-02 | **Нулевая декоративность.** Запрещены: градиентные фоны, тени ради глубины, фоновые изображения, иллюстрации, «карточки» вокруг единственного элемента, скевоморфные текстуры дерева/металла на грифе. Гриф рисуется линиями и точками. |
| NFR-D-03 | **Цвет несёт смысл.** Ахроматическая база (нейтральная шкала из 5–6 ступеней) + строго ограниченный набор семантических цветов: «в строе», «почти», «мимо», «нейтрально/нет сигнала». Никакие другие элементы интерфейса не используют семантические цвета. Акцентный цвет бренда — не более чем в одном месте экрана. |
| NFR-D-04 | **Типографика вместо украшений.** Не более 5 размеров в шкале (например 12 / 14 / 16 / 24 / 96 px) и не более 3 начертаний. Крупные числа (центы, частота) — с табличными цифрами (`font-variant-numeric: tabular-nums`), чтобы значения не «прыгали» при изменении. |
| NFR-D-05 | **Визуальный вес соответствует важности.** Целевая нота и команда «Подтянуть / Ослабить» — доминирующие элементы; частота в Гц, номер струны, эталон A4 — второстепенные, набраны мелко и нейтрально. |
| NFR-D-06 | **Иконки только вместе с текстом** (кроме общепринятых: закрыть, настройки, микрофон). Направление вращения колка обязательно дублируется словом. |
| NFR-D-07 | **Анимация минимальна и функциональна:** движение стрелки, подтверждение настройки, индикация захвата звука. Никаких декоративных переходов между экранами дольше 200 мс. Всё отключается при `prefers-reduced-motion`. |

| NFR-D-09 | **Пустые состояния и ошибки** оформляются текстом-инструкцией без иллюстраций: что произошло и что сделать (см. таблицу 8.5). |
| NFR-D-10 | **Копирайтинг:** повелительное наклонение и глаголы действия («Подтянуть», «Ударьте по струнам», «Включить микрофон»), одно и то же слово на кнопке и в результате действия, отсутствие вводных фраз и извинений. |

#### 8.2.2. Кроссбраузерность и прогрессивное улучшение

Базовый функционал (гриф, аккорды, гаммы) обязан работать **везде**, включая браузеры без доступа к микрофону. Аудиофункции подключаются как расширение.

| Возможность | Фолбэк при отсутствии |
|---|---|
| `AudioWorklet` | Сообщение о неподдерживаемом браузере с перечнем совместимых; гриф остаётся доступен |
| WASM-ядро DSP | Реализация на TypeScript с уменьшенной частотой анализа |
| `SharedArrayBuffer` (нет COOP/COEP) | Передача кадров через `postMessage` |
| `navigator.vibrate` (нет в iOS Safari) | Звуковой сигнал и визуальное подтверждение |
| Screen Wake Lock | Функция отключается без сообщения |
| `env(safe-area-inset-*)`, `dvh` | CSS-фолбэки на `vh` и фиксированные отступы |
| Установка PWA (iOS ограничена) | Инструкция «Поделиться → На экран «Домой»» в разделе «О приложении» |

Дополнительно: обязательная проверка на iOS Safari в приватном режиме (ограничения хранилища), в Chrome Android с включённым режимом энергосбережения (троттлинг таймеров) и при подключённых Bluetooth-наушниках как источнике звука (может стать активным микрофоном — предусмотреть выбор устройства и предупреждение о низком качестве BT-микрофона).

### 8.3. Экран тюнера (главный по важности)

Композиция сверху вниз (мобильный портрет):

1. **Строка состояния**: текущий строй (тап → смена), эталон A4, индикатор микрофона, кнопка «Стоп».
2. **Крупная целевая нота**: буква + октава, размер ≥ 25% высоты экрана. При автоопределении — с подписью «6-я струна».
3. **Шкала центов**: горизонтальная, −50…+50 ¢, нелинейная (центральные ±10 ¢ занимают половину ширины). Стрелка/бегунок. Центральная зелёная зона визуально обозначена.
4. **Инструкция действием**: одно слово крупно — «Подтянуть» / «Ослабить» / «В строе» + иконка направления вращения колка. Дублируется числом центов и частотой в Гц (мелким шрифтом).
5. **Ряд струн**: 6 кнопок с нотами; настроенные помечены галочкой; активная подсвечена; тап = ручная фиксация.
6. **Мини-гриф** (опционально сворачиваемый) — подсветка настраиваемой струны.

Требования к анимации: движение стрелки плавное (интерполяция между оценками), но без «инерции», скрывающей реальное положение; при отсутствии сигнала — стрелка бледнеет и возвращается в нейтраль за 1 с.

### 8.4. Экран анализа аккорда

1. Выбор аккорда: строка «Аккорд: Am ▾» + быстрые кнопки (Am, C, D, E, G, Em, «Открытые струны»).
2. Схема аккорда на грифе с точками прижатия.
3. Большая кнопка захвата: «Ударьте по струнам» → состояние «Слушаю… 1.2 с» с волновой анимацией.
4. Результат: на схеме каждая струна окрашена (зелёная/жёлтая/красная/серая «не прозвучала»), рядом список:
   `2-я струна · Си · −18 ¢ · подтянуть · [Настроить]`
5. Кнопки «Повторить» и «Настроить по одной струне» (переход в режим A/моно).
6. При низкой общей уверенности — баннер с подсказкой: играть медленнее, ближе к микрофону, не глушить струны.

### 8.5. Состояния и ошибки (обязательный перечень для дизайна)

| Состояние | Отображение |
|---|---|
| Микрофон не запрошен | Экран-объяснение + кнопка |
| Доступ отклонён | Инструкция, как вернуть доступ в настройках браузера (отдельно для iOS Safari, Chrome Android, десктопа) |
| Микрофон занят другим приложением | Сообщение + кнопка «Повторить» |
| Тишина / слишком тихо | «Дёрните струну» + подсказка о расстоянии |
| Перегрузка | «Слишком громко, отодвиньте телефон» |
| Слишком шумно | «Много фонового шума» + предложение строгого режима |
| Нестабильная высота | «Дайте струне звучать ровно» |
| Струна расстроена > 100 ¢ | «Похоже, это другая нота — проверьте, ту ли струну вы дёргаете» |
| Оффлайн | Работает; баннер не показывается (PWA) |

## 9. Тестирование и приёмка

### 9.1. Уровни тестирования

**Юнит-тесты DSP (Vitest + синтетические сигналы):**
- Чистая синусоида 73.4–1318 Гц с шагом 1 цент → ошибка детектора ≤ 0.5 цента.
- Сигнал с гармониками (h=1…10, спад −6 дБ/октаву) → ошибка ≤ 1 цент, октавных ошибок 0.
- Сигнал с негармоничностью (B = 5·10⁻⁵) → ошибка ≤ 2 цента.
- Отсутствие фундаментальной (подавлен h=1) → корректное определение F0 (проверка на «missing fundamental»).
- Аддитивный белый/розовый шум при SNR 20/10/0 дБ → деградация не более 3 центов при SNR ≥ 10 дБ; при SNR 0 дБ — статус «нет данных» вместо ложного значения.
- Затухающий сигнал (экспонента, τ = 1.5 с) → устойчивость до −40 dBFS.
- Синтезированные аккорды из 6 партиальных моделей с заданными расстройками (±5, ±10, ±25, ±50 центов на выбранных струнах) → режим B определяет знак отклонения в 100% случаев и величину с ошибкой ≤ 5 центов при уверенности «высокая».

**Тесты на реальном корпусе записей (golden set):**
- Не менее 120 записей: 3 гитары (акустика с металлом, нейлон, электро без обработки) × 6 струн × несколько уровней расстройки, записанных на 3 устройства (флагман Android, бюджетный Android, iPhone), в тихой комнате и с фоновым шумом.
- Не менее 40 записей аккордов (E, Am, G, D, C, F-баррэ, открытые струны) с известной эталонной расстройкой, полученной измерением каждой струны по отдельности.
- Эталон получают контрольным измерением профессиональным тюнером/анализатором; допускается синтетическое смещение высоты записанных отдельных струн с последующим микшированием — это даёт точную разметку.

**E2E (Playwright):**
- Запуск Chrome с `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>`; проверка всего маршрута: разрешение → детект → зелёная зона → подтверждение.
- Проверка сценариев отказа в доступе и ухода вкладки в фон.

**Ручное тестирование:**
- Матрица устройств/браузеров из 6.2, минимум по одному реальному устройству каждой платформы.
- Юзабилити-тест: 5 новичков, задача «настройте гитару», измеряется время и число обращений за помощью.

### 9.2. Критерии приёмки (Definition of Done релиза)

1. Все требования приоритета **M** реализованы и подтверждены тестами.
2. Метрики раздела 2.2 достигнуты на референсных устройствах.
3. Юнит-покрытие модулей `dsp/` и `domain/` ≥ 85% по строкам.
4. Lighthouse: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, PWA — установимо.
5. Прогон golden set: доля струн с ошибкой > 3 центов < 5%; октавных ошибок < 0.5%.
6. Ноль критических и высоких дефектов; известные ограничения задокументированы.
7. Проверка a11y: axe-core без нарушений уровня critical/serious; ручная проверка со скринридером (VoiceOver + TalkBack) на экране тюнера.
8. Адаптивность: на ширинах 320 / 360 / 390 / 414 / 768 / 1024 / 1440 px и в обеих ориентациях отсутствует горизонтальная прокрутка, ни один элемент не обрезан и не перекрыт безопасными зонами; смена ориентации во время активной настройки не прерывает работу микрофона; браузерный зум 200% не ломает раскладку.

1. Нужен ли backend хотя бы для сохранения пользовательских строёв/аппликатур между устройствами, или достаточно localStorage и ссылок?
2. Монетизация: планируется ли реклама или платные функции? Это влияет на макеты и на требование «без сторонних SDK».
3. Требуется ли поддержка инструментов помимо гитары/баса/укулеле (банджо, мандолина, балалайка, семиструнная русского строя)?
4. Нужен ли режим настройки по флажолетам (гармоникам на 5/7 ладу) — он популярен у части гитаристов и требует отдельной логики целевых частот?
5. Нужна ли поддержка неравномерных темпераций и исторических строёв, или достаточно равномерной с настраиваемым A4?
6. Есть ли брендбук/фирменные цвета, или дизайн разрабатывается с нуля?
7. Приоритет: скорость выхода MVP или максимальная полнота функций в первом релизе?
8. Требуется ли аналитика поведения пользователей, и в каком объёме (с учётом требований приватности)?

### В.2. Шрифты

Manrope (интерфейс, начертания 400/600/800) и JetBrains Mono (только числа: центы, герцы, номера ладов). Обе — OFL, подключаются self-hosted в формате woff2 с кириллическим сабсетом; загрузка через `font-display: swap`, метрики фолбэка настраиваются `size-adjust` для отсутствия скачка вёрстки. Шкала кеглей: 12 / 14 / 16 / 24 / clamp(64–96). Все числовые значения — `tabular-nums`.

### В.3. Правила направления (дополняют NFR-D-01…10)

| ID | Требование |
|---|---|
| NFR-D-22 | Свечение (`box-shadow`, размытые ауры) применяется **только** к трём объектам: стрелка шкалы центов, фоновая аура, активная струна на грифе. На тексте, иконках, кнопках, вкладках и карточках свечение запрещено. |
| NFR-D-23 | Одновременно на экране не более двух источников свечения. Проверяется на код-ревью. |
| NFR-D-24 | Семантические цвета (`--sig-*`) не используются ни для чего, кроме индикации строя. Кнопки, вкладки и ссылки используют `--brand`. |
| NFR-D-25 | Тема «День» — самостоятельная тема, а не программная инверсия: свечение выключено полностью, акценты затемнены до контраста ≥ 4.5:1. Переключение: авто по `prefers-color-scheme` + ручное в настройках. |
| NFR-D-26 | Аура фона меняет насыщенность по величине \|Δ\|: > 10 ¢ — розовая 55% / бирюзовая 10%; 3–10 ¢ — 25% / 30%; ≤ 3 ¢ — 0% / 60%; нет сигнала — обе 8%. При `prefers-reduced-motion` переходы 0 мс. |
| NFR-D-27 | Шкала центов нелинейна: `pos = \|c\| ≤ 10 ? 50 + (c/10)·25 : 50 + sign(c)·(25 + (\|c\|−10)/40·25)` — центральные ±10 ¢ занимают половину ширины. |
| NFR-D-28 | В режиме энергосбережения устройства `filter: blur()` заменяется плоской заливкой пониженной насыщенности (экономия GPU, требование NFR-P-06). |
| NFR-D-29 | Контраст пары `--sig-off` / фон (5.9:1) не допускает мелкого текста этим цветом: только кегли ≥ 16 px, стрелка и заливки. |
| NFR-D-30 | Автотест контраста всех пар токенов выполняется в CI; сборка падает при нарушении порогов из В.1. |

### В.4. Ритм и форма

Базовая сетка 4 px: 4 / 8 / 12 / 16 / 24 / 32 / 48. Радиусы: 2 px (мелкие метки), 8 px (плашки), 16 px (карточки), pill (кнопки). Толщина линий 1 px. Длительности анимации: 120 мс (отклик на касание), 200 мс (смена состояния), 600 мс (подтверждение настройки).
